# Plain industry names

1. Look in a standard vocabulary first (ISO 25010, AWS Well-Architected, SRE, DORA) and say where the
   term comes from. The familiar term wins over a clever one.
2. One term per concept everywhere: code, docs, UI and tickets.
3. Slugs and public identifiers are one-way doors; choose them deliberately.
4. A codename fits only where it names a system boundary.
5. Don't argue over names or taxonomy that change no behaviour.

Why: names are the interface people and agents reason with.
