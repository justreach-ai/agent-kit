# Interaction patterns

1. Name the person's starting point, the action they are trying to finish and where they lose time or context today. Try the current path first. If it already delivers the behavior, record that and move on.
2. Trace one reference interaction from input to outcome. A directory entry can point to an app. A recording, runnable example or source can show what its control actually does. Distinguish the behavior you observed from a detail you could only infer from a still image.
3. Decide what carries over. On a phone, check reachability, interruption and how Back restores the person's place. On a desktop, check keyboard focus, selection and how the next item opens. Reuse the product's own controls, tokens and words. Keep permission prompts tied to the action that needs them.
4. Describe the smallest change and one observable improvement that would justify keeping it. Carry that task into implementation and verification.

**Example.** A reading app hides articles already read. A technician returning to a long inspection needs the remaining checks. Offer a remaining-items filter, preserve the inspection order and let them return to the full list. Verify that reopening a check takes them back to the same inspection.
